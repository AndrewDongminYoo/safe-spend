# Safe Spend MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local-first Apps in Toss WebView miniapp that calculates how much money is safe to spend before the next income and previews the effect of a purchase.

**Architecture:** Use a React 18 and strict TypeScript Vite application with TDS Mobile for presentation, pure domain functions for money and calendar behavior, one context-based application store, and one versioned snapshot persisted through Apps in Toss `Storage`. Keep platform APIs behind adapters so domain behavior and UI states remain testable in Vitest without a Toss runtime.

**Tech Stack:** React 18, TypeScript, Vite 6, `@apps-in-toss/web-framework` 3.2.0, TDS Mobile 2.5.1, React Router 7, Vitest 5, React Testing Library, jsdom

**Spec:** `docs/specs/2026-09-22-safe-spend-design.md`

## Global Constraints

- Use the repository root as the application root; do not create a nested app or a worktree.
- Use `safe-spend` as `appName`, `써도돼` as the Korean display name, and `Safe Spend` as the English name.
- The current `create-ait-app` 0.2.7 TDS template is the scaffold reference, but it refuses this non-empty repository; reproduce its root files and run `npm exec -- ait init --app-name safe-spend --skip-input` instead of moving existing documentation.
- Use `apps-in-toss.config.ts`, which is the filename generated by the current CLI; update existing documentation that still names `granite.config.ts`.
- Use integer won values validated with `Number.isSafeInteger` and date-only `YYYY-MM-DD` strings.
- Persist one versioned JSON snapshot under `safe-spend:state` through Apps in Toss `Storage`; never use `AsyncStorage`, `localStorage`, or IndexedDB for financial records.
- Do not add login, a backend, MyData, SMS parsing, notifications, categories, reports, or cloud synchronization.
- Never send balances, amounts, expense names, memos, exact dates, or serialized state through analytics or error reporting.
- Show one home-screen banner only after primary content; use test ID `ait-ad-test-banner-id`, require `isSupported()`, use a `100%`-wide `96px` fixed slot, hide failures and no-fill, and destroy the slot on unmount.
- Use TDS Mobile for buttons, inputs, typography, list rows, dialogs, badges, and top navigation; custom CSS only composes product-specific layout and numeric summaries.
- Run only one install, build, or device job at a time; the planning-time load was above the machine's 10-core count.

## Review Focus

- A corrupt or future-version snapshot must show recovery without being overwritten until the user confirms reset; Task 4 pins this with repository and recovery tests.
- Calendar math must remain correct across leap years, month-end clamping, and daylight-saving boundaries; Task 2 uses date-only arithmetic and explicit fixtures.
- Repeated taps while a save is pending must not subtract a purchase or paid expense twice; Task 4 tests serialized mutation handling.
- A failed Storage write must keep the in-memory session usable, display a retry state, and persist the same snapshot on retry; Task 4 tests failure and recovery.
- Zero safe balance, negative input, decimals, and values above `Number.MAX_SAFE_INTEGER` must never produce `Infinity`, `NaN`, or silent rounding; Tasks 2 and 3 test all four classes.
